# PRD — 우리가족 자기계발 트래커

- 문서 종류: 제품 요구사항 정의서 (Product Requirements Document)
- 작성일: 2026. 11. 10.
- 수정일: 2026. 11. 10. — Phase 1 점검 결과 추가, 1-2 홈 화면 추가(PWA) 구현 반영
- 관련 문서: [BRD.md](BRD.md)

---

## 1. 제품 개요

가족 4명(부모 + 중·고등학생 자녀 2명)이 **각자 휴대폰**으로 운동·독서·공부를 기록하고, 주간 목표 대비 달성률을 **도장판·순위·통계**로 함께 보는 웹 앱.

- 핵심 목표: 가족 습관 만들기
- 성공 지표: 가족 주간 달성률 **70% 이상** 유지
- 제약: 무료 요금제만 사용, 일정은 여유 있게

## 2. 사용자 시나리오

1) 고등학생 자녀가 학원에서 돌아와 휴대폰으로 [기록] → "공부 2시간, 수학 문제집" 저장 → 도장이 찍힌다.
2) 엄마가 출근길에 [이번 주] 탭을 열어 가족 도장판과 MVP를 확인하고 응원한다.
3) 일요일 저녁 아빠가 [순위·공유] → "단톡방용 요약 복사"로 가족 단톡방에 주간 결과를 올린다.
4) 시험 기간이 다가오면 자녀가 [목표 수정]으로 공부 목표를 올리고 운동 목표를 낮춘다.

## 3. 현재 기능 명세 (Phase 1 — 구현 완료)

### 3.1 화면 구성 (하단 탭 4개)

| 탭 | 주요 요소 | 관련 코드 |
|---|---|---|
| 🏠 이번 주 | 가족 달성률, 도장 개수, MVP, 응원 문구, 구성원별 도장판(+초과 표시, "참 잘했어요" 도장), 목표 수정, **홈 화면 추가 안내 배너**(휴대폰에서만, 닫으면 다시 안 나옴) | `renderHome()`, `setupInstall()` |
| ✍️ 기록 | 구성원·항목 칩 선택, 양·날짜·메모 입력, 최근 기록 12건·삭제 | `renderLog()` |
| 📊 통계 | 주 이동(‹ ›), 주간 달성률·기록 수·MVP, 최근 8주 막대그래프, 연속 기록, 누적 합계 | `renderStats()` |
| 🏆 순위·공유 | 이번 주 순위(공동 순위 처리), 단톡방 요약 복사, JSON 내보내기·가져오기, 예시로 초기화, **홈 화면에 추가 안내 카드** | `renderRank()`, `summary()`, `setupInstall()` |

### 3.2 데이터 구조 (`data.js`)

| 데이터 | 필드 |
|---|---|
| `CATEGORIES` | `key`(exercise/reading/study), `label`, `icon`, `unit`(회/시간), `step`(1/0.5) |
| `members` | `id`, `name`, `emoji`, `color`, `goals{exercise, reading, study}` |
| `records` | `member`, `cat`, `value`, `memo`(40자), `date`(YYYY-MM-DD) |
| `cheers` | 응원 문구 배열 |

### 3.3 계산 규칙

- 주간 범위: 월요일 ~ 일요일
- 항목 달성률 = min(주간 합계 ÷ 목표, 1). 목표 0인 항목은 평균에서 제외
- 구성원 달성률 = 항목 달성률 평균 / 가족 달성률 = 구성원 달성률 평균
- 도장: 목표 1단위 = 1칸, 0.5 이상이면 반 도장
- 연속 기록: 오늘(없으면 어제)부터 거슬러 올라가며 기록이 있는 날 수
- 지난 주 달성률은 **현재 목표** 기준으로 계산 (목표 이력 미보관)

### 3.4 저장 방식과 한계

- 브라우저 `localStorage`(`familyTracker.v1`)에 저장 → **기기마다 데이터가 따로 있음**
- 가족 간 공유는 JSON 파일 내보내기 → 가져오기(중복 제외 합치기)로만 가능
- 아직 **배포 전**(내 PC의 `python -m http.server 8131`로만 실행)

### 3.5 홈 화면 앱 (PWA) — 2026. 11. 10. 추가

| 구성 요소 | 파일 | 내용 |
|---|---|---|
| 앱 정보 | `manifest.json` | 이름 "우리가족 자기계발 트래커", 홈 화면 이름 "가족도장판", 세로 화면·전체 화면(standalone) 실행 |
| 앱 아이콘 | `icons/icon-192.png`, `icons/icon-512.png`, `icons/apple-touch-icon.png` | 모눈종이 바탕에 빨간 도장(★). 안드로이드 마스크 아이콘 안전영역 안에 배치 |
| 오프라인 열기 | `sw.js` (서비스 워커) | **네트워크 우선**: 인터넷이 되면 항상 최신 파일, 안 될 때만 저장해 둔 파일로 열림 → 앱을 고쳐도 옛 화면이 남지 않음 |
| 설치 안내 | `index.html`, `app.js`의 `setupInstall()` | 아래 표 참고 |

설치 안내 동작

| 상황 | 화면 |
|---|---|
| 휴대폰 브라우저로 처음 열었을 때 | [이번 주] 위에 "홈 화면에 추가하면…" 배너 → [방법 보기]는 안내 카드로 이동, [✕]는 다시 안 보이게 저장(`familyTracker.installNudgeClosed`) |
| 크롬이 바로 설치를 지원할 때 | 안내 카드에 **[홈 화면에 추가]** 버튼 표시 → 누르면 설치 창 |
| 아이폰 / 안드로이드 | 기기를 감지해 해당 순서(공유 → 홈 화면에 추가 / ⋮ → 앱 설치)를 펼쳐서 보여줌 |
| 카카오톡 안에서 열었을 때 | "다른 브라우저로 열기" 먼저 하라는 안내 표시 (카톡 내부 브라우저는 홈 화면 추가 불가) |
| 이미 홈 화면 앱으로 실행 중 | 배너·안내 카드 모두 숨김 |

- 서비스 워커와 설치 기능은 **HTTPS 주소 또는 localhost**에서만 동작 → 가족 휴대폰에서 실제 설치는 1-1 배포 후 가능
- 기록 저장 방식은 그대로(`localStorage`). 홈 화면 앱과 브라우저는 같은 저장소를 쓰지만, **아이폰은 홈 화면 앱과 Safari의 저장소가 분리**될 수 있으므로 설치 후에는 홈 화면 아이콘으로만 기록하도록 안내 필요

## 4. 비기능 요구사항

| 항목 | 요구사항 |
|---|---|

| 단순함 | 별도 빌드 도구 없이 HTML·JS 파일 구조 유지 |

### Phase 2. Supabase를 활용한 데이터 저장 기능

**목표:** 4명이 각자 휴대폰에서 기록해도 **모든 기록이 한곳에 모이고 실시간으로 보이게** 한다. 파일 내보내기·가져오기 없이 가족 도장판이 자동으로 채워진다.

#### 2-1 데이터베이스 설계

| 테이블 | 주요 컬럼 | 설명 |
|---|---|---|
| `families` | `id`, `name`, `invite_code`, `created_at` | 가족 단위. 초대 코드로 합류 |
| `members` | `id`, `family_id`, `user_id`, `name`, `emoji`, `color`, `role`(parent/child) | 가족 구성원. 로그인 계정과 연결 |
| `goals` | `id`, `member_id`, `category`, `target`, `week_start` | **주별 목표 이력** 보관 → 지난 주 달성률을 그 주 목표로 정확히 계산 |
| `records` | `id`, `member_id`, `category`, `value`, `memo`, `date`, `created_at` | 기록 |
| `cheers` | `id`, `family_id`, `from_member`, `record_id`, `emoji`, `message` | 기록에 남기는 응원(👏🔥💪) |

#### 2-2 기능

| 번호 | 기능 | 설명 |
|---|---|---|
| 2-2-1 | 가족 로그인 | Supabase Auth 이메일 매직링크(비밀번호 없음). 첫 로그인 시 초대 코드로 가족 합류 후 "나는 누구?" 선택 |
| 2-2-2 | 클라우드 저장 | 기록·목표 저장/삭제를 Supabase로. `localStorage`는 오프라인 임시 저장용으로만 사용 |
| 2-2-3 | 실시간 반영 | Supabase Realtime으로 다른 가족이 기록하면 도장판이 바로 갱신 + "엄마가 독서 1시간 기록했어요" 토스트 |
| 2-2-4 | 응원 반응 | 최근 기록에 이모지 응원 누르기. 받은 응원 수를 홈 화면에 표시 |
| 2-2-5 | 기존 데이터 이전 | 현재 기기의 `localStorage` 기록·JSON 파일을 한 번에 업로드(기존 중복 제외 로직 재사용) |
| 2-2-6 | 권한 규칙 | 기록 입력·삭제는 **본인 기록만**(부모는 자녀 기록 수정 가능). 목표 수정은 본인 + 부모 |

#### 2-3 보안

- Row Level Security(RLS)로 **같은 `family_id` 구성원만** 조회·작성 가능
- 브라우저에는 Supabase `anon` 키만 사용 (`service_role` 키는 절대 넣지 않음)

#### 2-4 무료 요금제 점검

- 4인 가족 기록은 하루 수십 건 수준 → Free 플랜(DB 500MB) 한도 안에서 충분
- Free 프로젝트는 일정 기간 사용이 없으면 일시 중지될 수 있음 → 주 1회 이상 사용으로 유지

완료 기준: 4명이 각자 휴대폰에서 기록하면 다른 가족 화면에 몇 초 안에 반영되고, 가족이 아닌 계정으로는 데이터가 보이지 않는다.

### Phase 3. Gemini API를 활용한 AI 기능

**목표:** 기록을 보여주는 데서 그치지 않고, **AI 코치**가 칭찬·조언·목표 조정을 도와 가족 달성률 70% 이상을 유지하게 한다.

#### 3-1 기능

| 번호 | 기능 | 설명 | 화면 |
|---|---|---|---|
| 3-1-1 | 주간 AI 가족 리포트 | 일요일 저녁, 이번 주 기록을 요약해 "가장 많이 늘어난 사람", "다음 주 함께 해볼 것" 등 3~5줄 코멘트 생성. 단톡방 요약에 함께 붙여 복사 | 순위·공유 |
| 3-1-2 | 맞춤 응원 메시지 | 고정 응원 문구 대신, 구성원별 이번 주 실적·연속 기록을 바탕으로 한 줄 응원 생성(하루 1회 갱신) | 이번 주 |
| 3-1-3 | 말로 기록하기 | "오늘 수학 2시간이랑 줄넘기 했어" 입력 → 항목·양·메모로 자동 분리해 확인 후 저장 | 기록 |
| 3-1-4 | 목표 추천 | 최근 4주 실적을 보고 "공부 목표 6시간 → 5시간 추천(달성률 55%)"처럼 현실적인 목표 제안. **시험 기간 모드** 선택 시 공부 위주로 재배분 | 목표 수정 창 |
| 3-1-5 | 독서 메모 정리 | 독서 기록 메모를 모아 "이번 달 읽은 책" 목록과 한 줄 감상 정리 | 통계 |

#### 3-2 구조

```
휴대폰(앱) → Supabase Edge Function(Gemini API 키 보관) → Gemini API
                 ↑ 가족 로그인 확인 후에만 호출
```

- Gemini API 키는 **Edge Function 비밀값**으로만 보관, 브라우저 코드에 노출하지 않음
- AI 결과(주간 리포트 등)는 `ai_reports` 테이블에 저장해 같은 주에 반복 호출하지 않음 → 무료 한도 절약
- 모델: Gemini 무료 등급에서 쓸 수 있는 경량(Flash 계열) 모델 사용

#### 3-3 AI 응답 원칙

- 자녀(중·고등학생) 대상이므로 **비교·비난 없이 칭찬 중심**, 존댓말 대신 친근한 말투
- 순위 하위 구성원을 지목해 깎아내리지 않음
- AI가 만든 목표·기록은 **사용자가 확인을 눌러야** 저장
- 전송 데이터는 호칭·항목·양·메모만(실명·이메일 전송 안 함)

#### 3-4 무료 한도 대응

- 호출 빈도: 리포트 주 1회, 응원 하루 1회, 말로 기록·목표 추천은 사용자가 누를 때만
- 한도 초과·오류 시 기존 고정 응원 문구·수동 입력으로 자동 대체

완료 기준: 매주 AI 가족 리포트가 생성되어 단톡방에 공유되고, 목표 추천을 받아 조정한 뒤 가족 달성률 70% 이상을 유지한다.

| Phase 3 | Phase 2 안정화 후 | 주간 리포트 → 응원 → 목표 추천 → 말로 기록 → 독서 정리 순 |

마감일은 정하지 않으며, 각 단계 완료 기준을 만족하면 다음 단계로 넘어간다.
